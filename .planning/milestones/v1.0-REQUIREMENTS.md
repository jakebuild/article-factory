# Requirements v1.0: MVP

**Archived:** 2026-02-12
**Status:** ✅ ALL 37 REQUIREMENTS COMPLETED
**Core Value:** A programmable research-backed publishing engine that separates stable research from fully programmable writing, enabling dynamic prompt injection at runtime.

## v1 Requirements (COMPLETED)

All 37 requirements shipped in v1.0.

### CLI Foundation ✓

- [x] **CLI-01**: User can install article-factory via pip
- [x] **CLI-02**: User can create a new topic via `article-factory create --topic "..." --prompt "..."`
- [x] **CLI-03**: User can batch process topics from a file via `article-factory batch topics.txt`
- [x] **CLI-04**: User can check status of all topics via `article-factory status`
- [x] **CLI-05**: User can retry failed topics via `article-factory retry <id>`
- [x] **CLI-06**: CLI provides structured output (JSON mode available via flag)
- [x] **CLI-07**: CLI provides progress feedback during long operations

### State Management ✓

- [x] **STATE-01**: System persists topic metadata in SQLite database
- [x] **STATE-02**: System tracks notebook_id, artifact_ids, and status per topic
- [x] **STATE-03**: System supports crash recovery (idempotent operations)
- [x] **STATE-04**: System maintains retry_count for failed operations
- [x] **STATE-05**: Database uses WAL mode for concurrent async access

### Notebook Operations ✓

- [x] **NOTE-01**: System can create isolated notebook with timestamped slug format (YYYY-MM-DD__topic-slug)
- [x] **NOTE-02**: System triggers async deep research via NotebookLM API
- [x] **NOTE-03**: System polls for research artifact completion (45min timeout)
- [x] **NOTE-04**: System generates structured research synthesis
- [x] **NOTE-05**: System preserves notebooks permanently for knowledge compounding

### Content Generation ✓

- [x] **CONT-01**: System generates long-form article using user-provided dynamic prompt
- [x] **CONT-02**: Generated articles are 2,000-2,500 words (default)
- [x] **CONT-03**: Generated articles cite sources from notebook
- [x] **CONT-04**: System generates infographic image from notebook context
- [x] **CONT-05**: System generates executive audio briefing (8-10 minutes)

### Dynamic Prompting ✓

- [x] **PROMPT-01**: User can inject prompts inline via --prompt flag
- [x] **PROMPT-02**: User can provide prompts via file with --prompt-file
- [x] **PROMPT-03**: System applies safety constraints to user prompts
- [x] **PROMPT-04**: System enforces source-only citations in generated content

### Output & Export ✓

- [x] **OUT-01**: System exports all artifacts to structured output directory
- [x] **OUT-02**: Output format: YYYY-MM-DD/topic-slug/research_synthesis.md
- [x] **OUT-03**: Output format: YYYY-MM-DD/topic-slug/article.md
- [x] **OUT-04**: Output format: YYYY-MM-DD/topic-slug/infographic.png
- [x] **OUT-05**: Output format: YYYY-MM-DD/topic-slug/podcast.mp3
- [x] **OUT-06**: Output format: YYYY-MM-DD/topic-slug/metadata.json

### Error Handling ✓

- [x] **ERR-01**: System implements rate limiting to prevent API key suspension
- [x] **ERR-02**: System implements circuit breaker pattern for API failures
- [x] **ERR-03**: System retries failed operations (max 2 retries)
- [x] **ERR-04**: System logs all failures with context for debugging
- [x] **ERR-05**: System marks unrecoverable failures as FAILED status

## Out of Scope

Confirmed still out of scope:

| Feature | Reason |
|---------|--------|
| External API integrations | Beyond NotebookLM scope |
| Web crawling | NotebookLM handles source discovery internally |
| Hard-coded templates | Dynamic prompt architecture enables flexibility |
| Real-time collaboration | CLI automation focus |
| Multi-user accounts | Personal knowledge compounding focus |
| Built-in web UI | CLI-first design philosophy |
| Browser-based scraping | NotebookLM API handles source import |
